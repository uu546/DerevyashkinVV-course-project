# Диаграмма архитектуры PCMEF

Представлена диаграмма архитектуры системы, построенная на основе PCMEF в веб-траектории (Web).

![alt text](/docs/02-architecture/images/pcmef.png)

## Описание слоёв PCMEF

Архитектура PCMEF (Presentation–Control–Mediator–Entity–Foundation) представляет собой слоистую модель приложения, разделяющую ответственность между компонентами системы.

| Слой | Аббревиатура | Назначение | Реализация в проекте |
|------|--------------|-------------|----------------------|
| Presentation | P | Отображение данных, взаимодействие с пользователем, отправка запросов | Angular (клиентское приложение в браузере) |
| Control | C | Приём HTTP-запросов, вызов бизнес-логики, формирование ответов | REST-контроллеры (Spring Boot) |
| Mediator | M | Реализация бизнес-логики, правил, координация сущностей, управление транзакциями | Сервисные классы (Services) |
| Entity | E | Представление бизнес-сущностей (состояние и поведение) | JPA-сущности |
| Foundation | F | Доступ к данным, CRUD-операции, работа с БД и внешними системами | Репозитории (Repository pattern) |

## Правила зависимостей между слоями PCMEF

Основное правило архитектуры: зависимости направлены строго сверху вниз.

```
Presentation (P)
    ↓
Control (C)
    ↓
Mediator (M)
    ↓
Entity (E)  ←  Foundation (F)
    ↓
Database
```

## Детальные правила

| Правило | Описание |
|----------|----------|
| P → C | Слой Presentation обращается к Control через HTTP (REST API). Обратные зависимости запрещены. |
| C → M | Control вызывает бизнес-логику через сервисный слой (Mediator). |
| M → F | Mediator обращается к слою Foundation через репозитории. |
| M → E | Mediator использует бизнес-сущности, но сущности не зависят от логики Mediator. |
| F → E | Foundation работает с сущностями (сохраняет и возвращает их). |
| Нет обратных зависимостей | Нижние слои не знают о верхних слоях системы. |


- **Стабильность** — изменения UI не влияют на бизнес-логику и работу с данными  
- **Тестируемость** — каждый слой можно тестировать отдельно с использованием моков  
- **Переиспользование** — нижние слои можно использовать в разных интерфейсах  
- **Гибкость** — можно менять реализацию (например, заменить JPA на JDBC) без переработки всей системы

## Направление зависимостей на диаграмме пакетов

Описание зависимостей между слоями архитектуры PCMEF и тип взаимодействия между ними.

| От | К | Тип зависимости | Пояснение |
|----|----|----------------|------------|
| presentation | control | Сетевая (HTTP) | Клиентское приложение (Angular) отправляет HTTP-запросы к REST API |
| control | mediator | Через интерфейсы | Контроллеры вызывают сервисный слой через абстракции (интерфейсы) |
| mediator | foundation | Через интерфейсы | Сервисный слой использует репозитории для доступа к данным |
| foundation | entity | Прямая | Репозитории работают с бизнес-сущностями (JPA entities) |
| mediator | entity | Прямая | Бизнес-логика использует сущности для обработки данных |
