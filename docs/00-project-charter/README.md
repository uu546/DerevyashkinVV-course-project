## Описание ключевых сущностей

Ключевые сущности предметной области отражают основные объекты системы складского учёта и их характеристики.

| Сущность | Описание |
|-----------|-----------|
| **Product** | Товар (номенклатура). Содержит информацию о наименовании товара, единице измерения, артикуле и признаке скоропортящегося товара. |
| **Category** | Категория товара, используемая для группировки номенклатуры (например, «Стройматериалы», «Продукты питания», «Электроника»). |
| **Warehouse** | Склад - физическое место хранения товаров. Содержит сведения о складе и его характеристиках. |
| **Location** | Ячейка хранения внутри склада (стеллаж, секция, паллета, холодильная камера), предназначенная для размещения товаров. |
| **Inventory** | Остаток товара в конкретной ячейке хранения. Содержит информацию о количестве товара и реализует бизнес-логику изменения остатков при выполнении складских операций. |
| **Movement** | Движение товара. Фиксирует операции приёмки, отгрузки и внутреннего перемещения товаров между ячейками или складами. |
| **User** | Пользователь системы. Содержит данные учётной записи и роль пользователя. Роль **USER** предоставляет доступ к просмотру данных, роль **MANAGER** - полный доступ к операциям и управлению системой. |

## Матрица стейкхолдеров

Матрица стейкхолдеров позволяет определить ключевых участников проекта, их интересы, степень влияния и стратегию взаимодействия.

| Стейкхолдер | Роль / Влияние | Интересы / Ожидания | Влияние (1–5) | Отношение | Стратегия работы |
|-------------|----------------|---------------------|---------------|-----------|------------------|
| **Директор** | Заказчик, спонсор проекта | Прозрачность учёта, выполнение KPI, окупаемость инвестиций | 5 | + | Регулярная демонстрация результатов и показателей эффективности |
| **Менеджер склада** | Основной пользователь системы | Удобный интерфейс, автоматизация операций и отчётности | 5 | + | Сбор требований, участие в тестировании и согласовании функциональности |
| **Кладовщик** | Конечный пользователь | Быстрое выполнение операций, простота использования системы | 4 | +/- | Обучение работе с системой, сбор обратной связи |
| **Бухгалтер** | Потребитель учётных данных | Получение корректных документов и данных для бухгалтерского учёта | 3 | 0 | Согласование форматов документов и отчётности |
| **ИТ-отдел** | Техническая поддержка системы | Стабильность работы, безопасность и наличие документации | 3 | - | Проведение технических брифингов и передача документации |


## Карта пути клиента (Customer Journey Map)

### Сценарий: Оформление приёмки товара

**Роль:** Менеджер склада

| Этап | Цель | Действия | Мысли | Чувства | Болевые точки | Возможности улучшения |
|--------|--------|--------|--------|--------|--------|--------|
| **Подготовка** | Получить задание и документы | Принимает товар от поставщика, получает накладную | «Что должно быть в поставке?» | Сосредоточенность | Отсутствие электронной накладной | Система заранее отображает ожидаемую поставку |
| **Сверка** | Проверить соответствие поставки | Сравнивает фактический товар с накладной | «Сойдётся ли количество?» | Напряжение | Ручной поиск данных в Excel | Использование сканера штрих-кодов |
| **Ввод в систему** | Зафиксировать поступление товара | Вносит данные в систему | «Сколько времени это займёт?» | Усталость | Повторный ввод информации | Автозаполнение и массовая приёмка товаров |
| **Завершение** | Оформить документы | Печатает акт приёмки | «Всё ли оформлено правильно?» | Облегчение | Проблемы с печатью документов | Автоматическая печать документов |
| **Отчётность** | Передать информацию заинтересованным лицам | Передаёт акт бухгалтерии | «Работа завершена» | Удовлетворённость | Несогласованность данных между отделами | Единый источник данных для всех подразделений |

## SWOT-анализ

SWOT-анализ позволяет оценить сильные и слабые стороны проекта, а также внешние возможности и угрозы.

| | Положительные | Отрицательные |
|---|---|---|
| **Внутренние факторы** | **Сильные стороны (Strengths)** | **Слабые стороны (Weaknesses)** |
| | • Разделение ролей USER/MANAGER для контроля доступа | • Нет полноценной инвентаризации с записью расхождений (только просмотр остатков) |
| | • Поддержка массовых операций (batch-приёмка/отгрузка) | • Отсутствие модуля работы с поставщиками и контрагентами |
| | • JWT-аутентификация и шифрование паролей (BCrypt) | • Нет интеграции с бухгалтерскими системами (1С и др.) |
| **Внешние факторы** | **Возможности (Opportunities)** | **Угрозы (Threats)** |
| | • Внедрение сканеров штрих-кодов для ускорения операций | • Наличие готовых конкурентных решений (1С:Склад, МойСклад) |
| | • Расширение функционала (отчёты, аналитика, дашборды) | • Риск отказа пользователей от новой системы из-за привычки к Excel |
