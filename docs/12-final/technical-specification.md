
## Техническое задание
### 1. Введение
#### 1.1. Наименование системы
Система управления складом (Warehouse Management System)
#### 1.2. Назначение системы
Система предназначена для автоматизации складского учёта на малых и средних предприятиях, включая:
- Учёт товаров с привязкой к категориям и единицам измерения
- Оформление приёмки и отгрузки товаров (в том числе массовых операций)
- Перемещение товаров между складскими ячейками
- Просмотр актуальных остатков в реальном времени
- Разграничение прав доступа на основе ролей (USER / MANAGER)

#### 1.3. Цели создания системы

1. **Повышение точности учёта** — снижение расхождений
2. **Ускорение складских операций** — сокращение времени приёмки/отгрузки на 66%
3. **Обеспечение прозрачности** — онлайн-мониторинг остатков
4. **Удобство массовых операций** — добавление нескольких товаров за один запрос
5. **Разграничение доступа** — ролевая модель USER/MANAGER

#### 2.2. Требования к архитектуре (PCMEF)

##### 2.2.1. Описание слоёв

| Слой | Аббревиатура | Назначение | Реализация |
|------|--------------|------------|------------|
| **Presentation** | P | Отображение данных, взаимодействие с пользователем | Angular (браузер) |
| **Control** | C | Приём HTTP-запросов, валидация DTO, вызов сервисов | REST контроллеры (Spring Boot) |
| **Mediator** | M | Реализация бизнес-логики, транзакции | Сервисные классы (Spring Service) |
| **Entity** | E | Представление бизнес-сущностей в коде | JPA-сущности |
| **Foundation** | F | Доступ к данным (CRUD), работа с БД | Репозитории (Spring Repository) |

##### 2.2.2. Интерфейсы взаимодействия

| Интерфейс | Назначение |
|-----------|------------|
| **REST API** | Взаимодействие между Presentation и Control |
| **I*Service** | Интерфейсы сервисов (Mediator) для Control слоя |
| **I*Repository** | Интерфейсы репозиториев (Foundation) для Mediator слоя |

**Принципы взаимодействия:**
- Зависимости направлены сверху вниз: P → C → M → F → E
- Нижние слои не знают о верхних
- Использование Dependency Injection через конструктор

##### 2.3. Сохранность информации при сбоях

| Требование | Описание |
